**1. まず、長い読み取りから共有ロックを外す**

フィード・Memories・エクスポートを、次の2段階に分けます。

- ロック内：認証・閲覧権限を確認し、必要なレコードと関連情報を取得する。
- ロック外：ソート、ランキング、応答の組み立て、署名計算、転送を行う。

取得したデータは値をコピーするか、公開後に変更しない形にします。mapやsliceへの参照だけ持ち出す実装にはしません。

特にMemoriesは、ユーザー×月／日の索引を作り、全履歴の読み出しをなくします。これは読み取り自身を速めるだけでなく、投稿などの更新が待つ時間も減らします。

**2. 更新の単位に合わせて、状態とロックを分割する**

| 単位 | 担当する状態・操作 |
|---|---|
| ユーザー | プロフィール、セッション、日付別の投稿枠、自分の投稿索引 |
| 投稿 | 投稿本体、コメント、RealMoji、画像との関連 |
| 関係する2ユーザー | 友達申請・承認・ブロックに伴う一連の更新 |
| リージョン | 投稿期間の切り替え、通知対象の確定 |
| IP | 失敗回数とBAN判定 |

ロックは固定数のグループに分ける方式から始めるのが扱いやすいです。**ロックだけでなく、その配下のmapも分割**します。複数のロックが必要な場合は取得順を統一します。

ジャーナルへの追記は短い専用ロックで順序を管理し、状態への反映・成功応答との対応を保ちます。まずは正当性を優先して追記を直列のまま残し、ここが次の律速になった場合にまとめ書きを検討します。

**4. 通知の一斉起床をなくす**
